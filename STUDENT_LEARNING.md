# Student Learning Platform

## Architecture

The website is a static HTML, CSS, and JavaScript application published through GitHub Pages. Firebase Authentication identifies signed-in learners; Firestore stores lesson activity and private skill evidence. Firebase Hosting is not used to publish the website.

The course catalog is generated by `tools/build_course_catalog.py`. It currently contains 195 Math and Science lessons across Kindergarten through Grade 12. The learning path uses the existing lesson pages and saved-progress IDs rather than copying lesson content into a new system.

## Phase 1 Delivered

- `student-learning.html` is a student hub for saved activity, recent lessons, and links back to course work. Counts come from the signed-in student's records; new accounts see empty states rather than sample statistics.
- `courses.html` presents lessons in subject- and grade-specific topic units. Teachers can print a lesson sequence with lesson links; student-specific scores and progress states are excluded from print.
- Lesson progress and quiz attempts remain under `UserLessonProgress/{uid}/lessons/{lessonId}`. Client-authored results are treated as practice history, not authoritative mastery.
- `studentSkillMastery/{uid}/skills/{skillId}` is private and client-read-only in Firestore rules. Only trusted server code can write it. “Developing mastery” and “Mastered” require `verifiedBy: "assessment"`.
- The auth dashboard links to the hub and no longer displays invented XP or enrollment totals.
- Math Grades 1–5 lesson-tool IDs now match the IDs written by the existing grade lesson shell.
- Learners can set a 1–7 lesson weekly goal. The rolling seven-day count uses saved lesson activity only; the goal is private to the account when Firestore rules permit, otherwise it is explicitly device-local.
- Authenticated non-local origins sync device-saved lesson activity, practice attempts, and weekly goals to the signed-in account. Per-device revision markers make progress migration repeatable; localhost and file previews remain device-local.

## Phase 1 Limits

There is not yet a server-side assessment writer or trusted question bank, so no client can earn a verified mastery record yet. The UI shows no verified skills until trusted records exist. Existing client-writable lesson progress remains usable as private practice history but cannot award mastery.

Topic units are grouped from current course titles; the catalog does not yet contain authored skill standards or prerequisite relationships. Lessons remain reviewable and are not blocked by prerequisite checks. The current catalog covers Math and Science; programming lessons are not yet integrated into these paths. The student hub does not yet include assignments, goals, streaks, or teacher analytics.

## Remaining Phases

1. Complete Phase 1 with authored skill and prerequisite metadata, a server-graded assessment flow, cross-subject programming paths, and emulator-verified mastery writes.
2. Add multi-modal lesson metadata, accessibility preferences, learning goals, and non-exploitative achievements.
3. Connect existing teacher classes and assignments to course paths; add authorized progress analytics and a parent-linking design only after its consent model is implemented.
4. Audit the existing AI backend before adding a student tutor or writing coach. Keep provider credentials server-side and add student-specific rate and privacy controls.
5. Add timed test preparation and early-learning experiences using original content and age-appropriate privacy controls.
6. Document extension points for school organizations and SSO; do not enable institutional access without a verified identity and authorization model.

## Firebase Rules and Tests

The complete Firestore rules to upload are in [`firestore.rules`](firestore.rules). The learning hub uses the existing owner-scoped lesson-progress reads and the new read-only `studentSkillMastery` path. No migration or external API key is required for this Phase 1 work.

From `houselearning-home`, after confirming the active Firebase project:

```sh
firebase deploy --only firestore:rules
```

This command deploys rules only, not website files or Firebase Hosting. Do not deploy until the emulator authorization suite passes in an environment with Java installed.

Run available checks from `houselearning-home`:

```sh
python3 tools/build_course_catalog.py --check
node --test tools/test_*.mjs
python3 -m unittest discover -s tests -p 'test_*.py' -v
npm --prefix functions test
firebase emulators:exec --project demo-houselearning-teacher --only firestore "npm --prefix functions run test:rules-emulator"
```
